## [Unreleased]

### Added
- **`clean_text` says whether masking could have found anything — trust plan, Phase 1 item 2.** `*.clean_text.parquet` gains `mask_status`: `masked` (a span was replaced), `no_entity` (a candidate source covered the chunk and found nothing) or `not_masked` (none did, so the text is verbatim). A narrative chunk is covered when its document appears in the batch's enrichment entities or meta sidecar, or when the regex backstop is on; a table chunk only under the backstop, so table chunks read `not_masked` until they get candidates of their own (item 3). The stage logs a warning per batch with `not_masked` chunks. Additive; contract version `1.2`. Files written earlier back-fill on read: `masked` where `n_masked` is above zero, null otherwise.
- **The pdfium text engine matches MuPDF on rotated, indented, overprinted and upside-down text — P8.** `_same_block` now follows the rules measured on MuPDF with probe PDFs (see `decisions.md`): a same-row line, overprints included, continues a block; horizontal text splits where a line's origin lies right of the previous one's, at 0 and 180 degrees alike; vertical text uses mirrored baseline windows for up and down with no start condition; oblique text never continues by pitch. The rotated index's `Subsection` / `code` header splits as under PyMuPDF (12 headings each). pdfium sorts vertical text by position, so `read_chars` restores content order from the page's text objects, and a stray space pdfium injects between overlapping objects no longer splits a line. `test_pdf_block_parity.py` gains header, overprint, line-above and content-order cases at 0, 90, 180 and 270 degrees (5 for the originals).
- **The pdfium text engine groups blocks as MuPDF does — P8.** `_same_block` broke a block only on vertical proximity, so a heading and every paragraph after it became one block (`koala-habitat-audit`: 24 paragraphs under PyMuPDF, 6 paragraphs, 10 headings and 18 footers under pdfium). It now starts a block where the baseline pitch exceeds 1.5 of the new line's font size, and keeps a row's fragments in one block, measured along each line's writing direction from the character origins (`Char.origin`, read with `FPDFText_GetCharOrigin`). MuPDF does not break on a change of size or weight alone, so no such rule was added. New fixture `emu-spacing-variants.pdf` (six pages at different leadings and paragraph gaps) pins it; block line counts and element kinds now equal PyMuPDF's on every synthetic PDF but the rotated index, where MuPDF breaks a two-line column header that pdfium does not (12 headings against 8). Existing fixtures and digest pins are unchanged.
- **The pdfium image backend opens a flat PSD and takes a JPEG 2000 at 72 dpi — P8 (5 of 5).** A PSD raised `EOFError` at its first page because Pillow numbers its layers from 1 and frame 0 was sought; it is now its composite, as under MuPDF. MuPDF never reads a JPEG 2000's resolution box, so a 300 dpi file was a 96 by 72 pt page here against 400 by 300 under fitz; a JPEG 2000 is now always 72 dpi. Neither reads a PSD's resolution, so PSD already agreed (96 dpi). Page rects now match fitz on every case built for it. Item 4 of the plan needed no change: the only transform in extraction is womblex's own `Rect.transform`, shared by both backends, so the float32 difference was against the pre-port MuPDF call and not between backends.
- **The pdfium backend reports annotation appearances as drawings — P8 (3 of 5).** A page with annotations is read again from a flattened scratch copy of the document (never the main one, which would put widget text into the text layer), so a black Square annotation, a fake redaction that never touches page content, is a vector redaction under pdfium as it is under fitz; it was invisible. A NoView annotation is left out, as MuPDF leaves it out, though pdfium's display flatten keeps it. The widget case reports the same four drawings as fitz.
- **The pdfium table finder works in the displayed page's frame — P8 (1 of 5).** `find_tables` carries characters and ruled edges through the page's rotation matrix before pdfplumber sees them, as MuPDF does, so a landscape table on a rotated portrait page reads as horizontal text. `bilby-foi-documents-index` now gives 78 by 11 on page 1 and 74 by 12 on the rest, with all 858 cells on page 1 identical to fitz's; it was 39 columns, the text running vertically in the unrotated frame. The cause was rotation, not word segmentation as P7 supposed.
- **The pdfium backend finds tables — P7.** `ingest/pdf/_tables.py` feeds pdfplumber's `TableFinder` (lines and text strategies, its defaults) with ruled edges read from pdfium's path segments and the character boxes `_text.py` already holds, so `find_tables` no longer raises on `backend="pdfium"` and pdfminer never parses the page. Edges and character dicts are built lazily: the text strategy reads no edges, and a page with no ruled edge never builds the character table. A grid drawn as one path keeps its inner rules. On the synthetic PDFs it takes about half fitz's time per page and agrees on row and column counts except the text strategy's column count on `bilby-foi-documents-index` (39 against 11), which P8 inherits.

### Fixed
- **The pre-run model check no longer pollutes model provenance.** Building a model only to confirm it loads was being recorded as if the run had used it — `utils/model_check.check_models` now runs its whole pass under `model_registry.suppress_use_recording` and `models.suppress_recording`, so a model it builds to check never lands in the `womblex.slot_models` / `womblex.models` footer keys, and a run that never actually OCR'd no longer shows an OCR model. The PII-context check already built its model without recording it (`resolve(...).factory(...)` bypasses `record_use` entirely), which was the opposite inconsistency; it is now the general rule, not an accident. Two call sites cache the model they build (`get_layout_analyzer`, `get_paddle_reader`'s reader cache, `process/spellfix.load_dictionary`'s `lru_cache`) — each now checks `model_registry.recording_suppressed()` to bypass its own cache while the check is active, so the run's own first real build afterwards is not a cache hit that silently skips `record_use` for good. The bundled spellfix dictionary had a second cache under that one: `_dictionary` was itself `lru_cache`d around `resolve_local_model_path`, so after the check the run's build reused the check's unrecorded resolution and `womblex.models` never named the dictionary; resolution now runs on every call and only the Hunspell parse is cached.

### Changed
- **DBOS replaces the job queue, worker and stage runner's queue half — trust plan, Phase 0.** `cloud/queue.py` and `sql/womblex_jobs.sql` are deleted. An extraction batch and a downstream stage are DBOS workflows (`cloud/workflows.py`); `cloud/jobs.py` (`RunBoard`) enqueues and reads them; a worker (`cloud/worker.py`) joins only the queues it can serve. A finished batch or stage unit is a recorded step and is not re-run; a re-enqueue attaches to the same workflow. `WOMBLEX_DB_DSN` is now the DBOS system database (a Postgres URL); without it a local SQLite file is used, so `enqueue`, `worker` and `jobs` no longer require a database server (the file is `.womblex/dbos.sqlite` under the working directory, or `WOMBLEX_DBOS_PATH`, so processes sharing a run must share it). `jobs`, `finalize --dsn` and `run-stage --dsn` read a database no writer has migrated as empty. `worker --once` exits after this worker's first completed workflow. A stage missing an upstream sidecar fails without retries. **Breaking:** `womblex worker` loses `--run-id` and `--stale-timeout`; a worker's default id is the host name, not `host:pid`; runs queued in `womblex_jobs` are drained or re-enqueued, not migrated; a failed stage ends its run's coordinator, and re-dispatching it returns the recorded failure. See `decisions.md`.
- **A missing `text_source` overlay refuses the stage before any batch runs — trust plan, Phase 1 item 1.** Locally, chunk, enrich and money check every batch for the declared `*.normalised_text` / `*.spellfix_text` sidecar up front (`text_overlay.require_overlays`) and raise `MissingOverlayError` naming the batches that lack it; they no longer warn and fall back to verbatim text with a zero exit. `run-stage --shards` and the per-stage `chunk` / `enrich` / `money --shards` commands report it as a refusal and exit 1, without a traceback. On the object store, `run_stage_remote` checks every base ready to run before processing any, so a gap in a later batch no longer leaves earlier ones published; a base still waiting on a required input stays `NotReady`. **Breaking:** a run that relied on the fallback now fails; run the overlay's stage first or set `text_source: elements`.
- **PyMuPDF is removed — F2.** `ingest/pdf/_fitz.py`, `open_document`'s `backend` argument, `DEFAULT_BACKEND` and the `pymupdf` dependency (with its mypy override) are gone; pypdfium2 + pdfplumber are the only PDF libraries, and `import fitz` appears nowhere. The MuPDF values the parity tests measured against it are pinned as literals in `test_pdf_block_parity.py` and `test_pdf_text.py`; `test_pdf_fitz.py` and the fitz-versus-pdfium comparisons are deleted. The CI image-stamp step no longer filters a `fitz` notice off stdout, and the Docker comments no longer name PyMuPDF. `docs/plan-permissive-deps.md` is deleted; its declared behaviour changes are in `decisions.md`. `docs/accuracy/BACKEND_PARITY.md` is generated by womblex-benchmark and still names the plan.
- **The default PDF backend is pdfium — F1.** `open_document` opens PDFs and images with pypdfium2 + pdfplumber unless a caller names `backend="fitz"`, which stays until F2. Over `fixtures/synthetic/` the two backends agree on doc type, per-page plan operation, `has_text_layer`, vector-redaction counts, table counts and form-field counts; native-text CER between them is 0.0000, and pdfium is the faster on most files. **Declared changes:** calling `extract_text` directly no longer opens XPS, EPUB, MOBI, CBZ or SVG, nor an image format MuPDF decodes and Pillow does not (WebP and AVIF are new); `content_digest` moves for `quokka-care-decision-notice_redacted.pdf` and `numbat-scanned-survey-page.pdf` (re-pinned; `koala-habitat-audit.pdf` is unchanged), and `test_default_digest` now guards on the pypdfium2 version (5.14.0); paragraph segmentation, bold-based heading detection, `image_count` and OCR renders (anti-aliasing) may differ slightly. The womblex version and `uv.lock` pin the library, so the run stamp records no PDF library version.
- **The test suite runs on synthetic fixtures; no third-party data is vendored.** `fixtures/fixtures/` (FUNSD, IAM-line, DocLayNet and womblex-collection samples, 32 MB) is removed. `fixtures/synthetic/` holds invented Australian-animal documents in the same shapes (budget DOCX, redacted, audit and scanned PDFs, a rotated printed-spreadsheet manifest and a schedule, register CSV, statistics XLSX, scanned forms, lines and pages with their text), written deterministically by `fixtures/synthetic/generate.py` and committed (under 700 KB); `tests/_synthetic.py` names them. About 240 tests that skipped without the vendored or full fixture set now always run, among them the store and run tests, `test_spreadsheet_print`, `test_integration` and `test_fixtures`. `test_default_digest` is re-pinned on the synthetic set, extraction code unchanged. `test_bench_ocr_accuracy` is maintainer-only: marked `benchmark`, it reads a local copy of the benchmark set at `fixtures/fixtures/` (now git-ignored). CI runs `-m "not benchmark"` and gains a Postgres service, so the job-queue tests run there too.
- **Unfiltered redaction pages are recorded, not just warned — L3f.** `detect_redactions` warns once per document (not once per page) naming the pages it ran without exclusion zones, and returns them as `RedactionReport.unfiltered_pages`. `redact --shards` writes them to each `*.redactions.parquet` footer (`womblex.redaction_unfiltered_pages`), and `unfiltered_redaction_pages` reads them beside the layout sidecars, so pages with no layout row at all (shards extracted with redaction off) are no longer missing from it.
- **OCR reads the persisted layout regions — L3b.** `_layout_blocks_and_tables` takes the layout step's `PageLayout` for the page instead of calling an analyser, mapping its normalised boxes onto the OCR render; a page whose layout is `empty` or `error`, or with no layout step (`extract_text` without `layout=`), falls back to whole-page OCR text. **Breaking:** `extraction.ocr.layout_model` / `layout_options` are removed, and a config that still sets them is refused (naming the replacement) rather than silently running the default model; the one layout model is `layout.model` / `layout.options`, and `extract_text` / `extract_pdf_with_plan` / `extract_with_plan` lose their `layout_model` / `layout_options` parameters. The OCR-versus-layout pixel-dimension check goes, as both renders are the OCR render by construction. Redaction still runs its own analyser until L3c. `tests/test_default_digest.py` keeps every pin: its `extract_text` call now passes the default config's `LayoutSettings`, as the batch does, since a call without `layout=` no longer runs layout (and so shifts the Auditor-General digest). Callers that want table regions on OCR pages must pass `layout=`.
- **Redaction reads the persisted layout regions — L3c.** The raster-page exclusion zones come from the layout step's regions (`detect_redactions(..., layout=...)`): `womblex run` passes the regions it just found, `womblex redact --shards` reads each batch's `*.layout_regions.parquet` (`store.layout_output.read_page_layouts`), and `validate-redactions` runs the default layout model over each document, having no shard. A page with no usable layout (status `error`, or no row) is detected without exclusion zones and logs a warning naming the document and page; `store.layout_output.unfiltered_redaction_pages` lists them from the sidecars. **Breaking:** `redaction.layout_model` / `layout_options` are removed and refused if still set (`layout.model` / `layout.options` choose the one model); standalone `redact` no longer loads a model, so the pre-run check has nothing to do for it. Exclusion zones are now derived from the 200 dpi layout render, normalised and mapped onto the 150 dpi redaction render, which can move a zone edge by a pixel. `docs/layout.md` documents the unfiltered-pages query.

- **`run-stage layout` reruns layout locally — L3d.** `process/layout_stage.layout_shards` (contract `layout`, `--shards` only) re-reads each batch's PDF and image sources through `SourceResolver` (`--ingest` names a moved corpus), reruns the layout step and replaces `*.layout_regions.parquet`, leaving elements, tables and redaction as extracted. A batch whose sidecar fingerprint equals the config's is skipped (`--force` overrides); the fingerprint now also records `consumers` (whether OCR and the redaction filter select pages under `page_scope: consumers`), so switching either reruns, and a sidecar written before it reruns once. A rewritten sidecar records `layout_redaction_consumed = false`, as redaction ran against the regions it replaced. A batch with a document that cannot be found or analysed is left untouched. `store.layout_output.layout_fingerprint_statuses` compares the sidecar's fingerprint with the elements footer (`match` / `mismatch` / `unknown`, the last for runs extracted before layout). The `layout` model-check scope loads `layout.model` for the stage. `layout` joins `PIPELINE_ORDER` after `extract`, outside `DOWNSTREAM_STAGES`; `StageContract` gains `needs_sources`, which a store run refuses until L3e. The README's layout-not-supported note is removed.

- **`run-stage layout` runs against a store — L3e.** The distributed runner gives a `needs_sources` stage a per-document fetcher over the ingest store: each manifest row's `source_relpath` is its ingest key, the download is checked against `source_hash`, and a missing, moved or changed document is an error for that document, which fails its batch and leaves the published sidecar as it was. A batch whose fingerprint already matches fetches nothing. `--ingest` on `run-stage --store` (default `$WOMBLEX_INGEST_URI`, else the store) and the worker's ingest store reach the runner through `run_stage_remote(..., ingest=)`; the store refusal L3d added is gone. `layout_shards` raises when a batch could not be analysed, so a stage that published nothing new no longer reads as done. Completes the layout stage (L3).

### Added
- **Layout regions are recorded per page — L3a.** A top-level `layout:` section (`model`, `options`, `page_scope`) names the one layout model, and the extraction batch runs it once per selected page after profiling and before OCR, writing `batch-NNNN.layout_regions.parquet` (`store/layout_output.py`): normalised top-left boxes, label, block type, confidence, and a status row (`empty` / `error`) for a page that found nothing or failed. A layout fingerprint (model, model digest, options digest, dpi, page scope, schema version) is in the sidecar's footer and in the `*.elements.parquet` footer. `page_scope: consumers` analyses OCR-routed pages plus, with the redaction layout filter on, pages without vector redactions; `all` analyses every page. Contract version `1.0` to `1.1` (new `layout_regions` role, sensitivity `none`). OCR and redaction still call their own analysers, so no element changes. `config_digest` moves for every config, as the config gained a section. New `docs/layout.md`. First two merges of the layout stage (L3a-i, L3a-ii).
- **The pdfium backend extracts text — P6.** `ingest/pdf/_text.py` reads pdfium's characters in content order and rebuilds lines, blocks, spans and words in womblex, each line along its characters' writing direction, so `plain_text`, `text_dict`, `words` and `text_blocks` no longer raise on `backend="pdfium"` (`find_tables` followed in P7). It matches the locked MuPDF where measured: the effective font size (the `Tf` size scaled by the character matrix — pdfium alone reports 1.0 wherever a producer sets `1 Tf`), characters off the page dropped, and no line-end hyphen joined, since MuPDF 1.27.2 joins none under `TEXT_DEHYPHENATE`. Bold is font weight, ForceBold or the name. Against fitz over the vendored PDFs' first 40 pages: text similarity 0.951 minimum, 0.997 mean. Multi-column reading order is P8's.
- **The last fitz-built test fixtures are on the reportlab builder — P4b.** `test_grid_projection`, `test_table_reconstruction`, `test_extract`'s block-count and prose-gate tests and `test_spreadsheet_print` build and open pages through `tests/_pdf_builders` and `open_document`; `FitzDocument.wrap`, the tests' bridge, is deleted with the constructor path it used. The prose-gate test asserts the text strategy over-claims on its page, so it fails if the gate stops being exercised. fitz remains in tests only where it is the subject.
- **Standalone images are ingested by `womblex run`, the cloud enqueue and the console.** `.png .jpg .jpeg .tif .tiff .bmp .gif .jp2` join `SUPPORTED_EXTENSIONS` in `cli/_shared.py`, so every entry point enumerates them through `select_supported`; each opens as a one-page document on the orchestrator's OCR path, as `extract_text` already handled. WebP and AVIF stay out until the default backend opens them. A corpus with images in a subdirectory is now refused as nested, where those images were previously ignored.
- **The pdfium backend opens raster images — P5b.** `ingest/pdf/_image.py` presents a raster image through Pillow as image-only pages, one per frame, sized by MuPDF's page-rect rule: the horizontal resolution on both axes, 96 when undeclared, 72 outside 72..4800, EXIF orientation applied. It reads each format's own resolution fields, since Pillow's `info["dpi"]` reports 72 or 1 where MuPDF sees none. `_pdfium_doc.open_document` sniffs the PDF header and hands anything else to it; it opens MuPDF's image formats that Pillow decodes (PNG, JPEG, TIFF, BMP, GIF, JPEG 2000, PNM, PSD) plus WebP and AVIF, and every frame of an animated GIF, PNG or WebP or an MPO JPEG is a page where MuPDF gave the first; another format is a `ValueError`. 16-bit grey is scaled to 8 bits rather than clipped. Renders resample bilinearly, the Pillow filter closest to MuPDF. Images stay on the orchestrator path. Twelfth merge of the permissive-dependencies plan (P5b).
- **The pdfium backend opens PDFs — P5a.** `ingest/pdf/_pdfium_doc.py`, registered as `open_document(path, backend="pdfium")`, presents pypdfium2 pages in the seam's top-left space: page rects, rotation matrices, rendering (sized by the new `types.render_box`, MuPDF's round-out rule), image objects, filled paths with their fill colour, and widgets, with form XObjects composed to page space. Against fitz on every vendored fixture PDF the geometry agrees; fill colours are quantised to 1/255 and anti-aliasing differs. Text and tables raise until P6 and P7, so the default backend is still fitz and no digest moves. `PdfBuilder` gains lines, text fields and page rotation. Eleventh merge of the permissive-dependencies plan (P5a).
- **Test PDFs are built on reportlab — P4a.** `tests/_pdf_builders.PdfBuilder` draws pages, text, filled rects and images in top-left points with fitz's defaults (A4, 11pt Helvetica), writes reproducible bytes (`invariant=1`) and reads back through `open_document`, so tests follow the default backend. `test_redaction`, `test_model_registry`, the two `_image_to_pdf` copies and `test_extract`'s page-break tests build through it. Against the fitz builders it is identical where it matters: the same redaction boxes on all seven vector cases, the same `PageProfile` and word boxes on text pages, and pixel-identical renders of image pages. Tenth merge of the permissive-dependencies plan (P4a).
- **The permissive PDF dependencies are in the lock — D1.** `pypdfium2`, `pdfplumber` (pinned exactly, `==0.11.10`) and `pillow` join the core dependencies and `reportlab` joins `[dev]`, ready for the pdfium backend (P5 to P7) and the reportlab test builders (P4). Nothing imports them yet. pdfplumber 0.11.10 requires pillow 12.2 or later, so the lock moves pillow from 12.1.1 to 12.3.0. Its own commit, separate from the P3b port. Ninth merge of the permissive-dependencies plan (D1).
- **The OCR, spreadsheet-print and redaction paths now read pages through the PDF seam.** `strategies_scanned.py`, `spreadsheet_print.py`, `redact/stage.py` and `redact/batch.py` take `ingest/pdf` `Page`/`Document` objects, so `fitz` is imported only in `ingest/pdf/_fitz.py`. The transitional `ingest.pdf.native`, the adapter's `native` properties and `extract._pixmap_to_array` are deleted; `_ocr_page`, `_ocr_image_regions` and `_layout_blocks_and_tables` render through `Page.render`, `_ocr_image_regions` takes its rects from `Page.images()`, and vector redaction reads `Page.drawings()`. `content_digest`, `RedactionReport` geometry and spreadsheet-print output are identical to the pre-port values on every vendored fixture. On rotated spreadsheet-print pages, spans move by up to 1.5e-5 pt, because `Rect.transform` is double precision where MuPDF's `Rect * Matrix` rounds to float32. Eighth merge of the permissive-dependencies plan (P3b).
- **Detection and page profiling now read pages through the PDF seam.** `detect.py`, `page_profile.py` and `morphology.py` take `ingest/pdf` `Page`/`Document` objects and no longer import fitz: `detect_document_type` opens through `open_document`, `profile_pages` takes a `Document`, and the morphology helpers rasterise via `Page.render` (RGB, so the grayscale conversion is unchanged). The `pymupdf_layout` warning filter and the stdout capture around `find_tables` move into the fitz backend, where the noise originates. `FitzPage.find_tables` already extracts cell text, so the manifest signal reads `FoundTable.rows` instead of calling `extract()` lazily. `PageProfile` and `DocumentProfile` are identical to the pre-port values on all 48 fixture PDFs and images (first 20 pages). The benchmark's `backend_parity.py` opens through the seam too, as its `fitz.open` + `profile_pages(doc)` would otherwise break. Seventh merge of the permissive-dependencies plan (P3a, paired with womblex-benchmark).
- **The native extractors now read pages through the PDF seam.** `extract.py`, `orchestrator.py`, `forms.py`, `grid_projection.py` and `strategies_file.py` take `ingest/pdf` `Page`/`Document` objects and no longer import fitz; `extract_text` opens through `open_document`. `page_profile`, `strategies_scanned` and `spreadsheet_print` still want MuPDF objects until P3, so the orchestrator hands them the backend's own via the transitional `ingest.pdf.native`. The fitz backend now omits `flags` rather than passing 0 when not dehyphenating, so MuPDF's default text flags survive. `content_digest` is unchanged (`test_default_digest` passes unedited). Sixth merge of the permissive-dependencies plan (P2).
- **The PDF seam's first backend, and one entry point to open a document.** `ingest/pdf/open_document(path, backend=…)` resolves its backend through `_BACKENDS` at call time, and `ingest/pdf/_fitz.py` adapts PyMuPDF onto the protocols — MuPDF's dicts, tuples and pixmaps in, `types.py`'s dataclasses and arrays out. Two shapes differ from the fitz calls they replace, deliberately: `render` returns an `(h, w, 3)` uint8 RGB array, absorbing `_pixmap_to_array` and dropping the alpha branch no caller used; `images()` returns one `PageImage` per *draw*, de-duplicating xrefs first, which makes the latent N² duplication in `_extract_images_from_page` unreachable through the seam (`get_images` lists draws, not resources — see `docs/decisions.md`). No digest moves, since no fixture page repeats an xref. `test_public_api` now asserts that neither `import womblex` nor importing the seam loads *any* PDF backend, not just fitz. Nothing calls the seam yet; P2/P3 port the extractors onto it. Fifth merge of the permissive-dependencies plan (P1b).
- **A backend-neutral PDF vocabulary, ahead of replacing PyMuPDF.** New `ingest/pdf/types.py`: `Rect` (normalising, with `transform` for the rotated-page path), `Span`/`Line`/`Block`, `Word` as an 8-field NamedTuple so `grid_projection`'s positional slicing is untouched, `FoundTable`, `Drawing`, `Widget`, `PageImage`, and the `Page`/`Document` protocols. The page methods are typed rather than fitz-shaped, and the module has no third-party imports at runtime (numpy appears under `TYPE_CHECKING` for `render`'s annotation alone), so importing it loads no PDF library. Written as one merge P1 is ~580 lines, so it ships as the vocabulary then the backend. Fourth merge of the permissive-dependencies plan (P1a).
- **A backend-parity baseline, and Phase 0's measurements on the record.** womblex-benchmark gains `accuracy/backend_parity.py` + `accuracy/test_backend_parity.py`, publishing `docs/accuracy/BACKEND_PARITY.md` here: the between-backend half of the plan's H-B, which needs no ground truth. With one backend it runs as a repeatability baseline — the same fitz build twice over 45 fixtures, all identical — comparing open failures, page count, doc type, every `PageProfile` field, per-page plan operation, element kinds, `content_digest`, table shapes, form fields and full per-page redaction geometry. PDFs are capped to 20 pages, and because the comparison is reflexive the suite asserts a floor (every fixture opened and produced elements) so uniform breakage cannot read as agreement. `docs/decisions.md` records Phase 0's figures: pdfminer tracks fitz closely (median CER 0.010) but costs 67x per page, so the speed gate rejects it and a pypdfium2 character rebuild is P6's candidate; pdfplumber's table finder is faster than fitz's and no better calibrated; MuPDF derives a standalone image's page rect from its own DPI tag, falling back to 96dpi; and `get_images` lists draws rather than resources, which the earlier draft had backwards. CER against transcripts waits on the ground-truth revision. Third merge of the permissive-dependencies plan (H-B, paired with womblex-benchmark).
- **The pre-run model check reaches the paid services — completes requirement 25.** `utils/model_check.py` now sends one minimal request to every Isaacus model an enabled stage calls (enrich, embed, AI chunking; scopes `enrich` / `embed` / `chunk`, so a worker refuses only those stage jobs), through the same client the stage builds, and calls `ping()` on any registered model that has one: `MistralOCRReader` sends a one-token Bedrock request, `OllamaOCRReader` checks the server lists the model. Both run at `load` and `smoke` alike. `womblex run` therefore stops before extraction when a later Isaacus stage cannot reach its deployment, rather than after the stages before it were paid for. - **The reviewer-facing renderer is byte-deterministic, and a test says so.** `process/renderer.py` was already a pure, order-preserving projection over an ordered element list; this pins that guarantee formally so the ground-truth digest chain that records `baseline_digest` is load-bearing rather than decorative. The render reads no clock, path or process state and iterates no mapping in output order — a rendered table's row order comes from `sorted` in `_element_to_table_data`, and cell and field values are `str` by schema, so a table number renders verbatim with no default-`repr` path. - **A ground-truth segment can be rendered to reviewer-facing markdown (narrative slice).** New `process/renderer.py` turns a segment's element run into the markdown a human reads and corrects. Ground truth is keyed to element identity, not to this rendering — reading order and formatting are presentation and regenerable, the corrected text is not — so the renderer is a pure, order-preserving projection that invents nothing beyond a closed set of structural delimiters. This first merge covers the narrative kinds: they render verbatim, one blank line between elements, via the chunker's own `reassemble_narrative` rather than new projection code, so a reviewed unit and a chunked one occupy one coordinate space and cannot drift. Redaction markers in the element text survive unchanged because nothing here rewrites text. `rendered_order()` returns the element `order` sequence as it appears in the output — the handle a reading-order check compares against the source element sequence without parsing the markdown back apart. A non-text element contributes nothing rather than being dropped from a position it never held; on a narrative-only source the two states are identical, which is the per-page cohort the renderer is first proved against. Table and form rendering — the other members of the closed structural set — and the formal cross-process determinism guarantee land in the following merges.
- **Ground-truth segment boundaries come from the element stream, not from chunks.** New `process/segmenter.py` cuts an ordered element stream into contiguous ranges a human can review in one sitting — the unit ground truth is keyed to. Boundaries are a function of the elements and `SegmentationConfig` alone, deliberately not of chunk boundaries: the chunker is one of the stages measured against ground truth, so deriving units from it would make the reference move whenever the thing under test moved. Two constraints compose in order — a page ceiling partitions the stream into runs no wider than N pages, then `utils/token_packer.pack_by_tokens` packs each run to the token budget. That is the existing Isaacus request packer rather than a second greedy grouper, including its solo path, so this change is the element-kind projection layered over it and not a new algorithm. Splits happen only between elements, which is what makes "a table is never split" structural rather than a rule to enforce: cells nest inside their table element and fields inside their form, so a boundary cannot fall within one. The one shape the budget cannot honour is a single element larger than it — there is no boundary inside an element to split at — so it is emitted alone and flagged `oversize` rather than silently over budget or silently dropped; `segmentation.oversize='error'` refuses the document instead, for a caller that would rather not review one. An element whose count lands *exactly* on the budget is within it and is not flagged, which the packer's own `>=` solo test would otherwise have claimed. Elements that contribute no text — page breaks, sheet metadata — are carried by whichever segment they fall in rather than skipped, because segments of one document have to tile it: the union of their ranges is the document's full range, which is what lets a future re-cut of boundaries be arithmetic over existing corrections rather than a second human re-review. That guarantee is enforced rather than assumed: every producer assigns `order` as a counter incremented only on append, so one document's stream is contiguous, and a stream with a gap in it — a caller that filtered out the page breaks, or took a page range — is refused. Segments cut from a subset would report ranges that silently fail to tile, which is the one way this guarantee could be lost without anything looking wrong. A DOCX or spreadsheet, having no page concept, is bounded by the budget alone. `page_range` is `None` whenever no element in a segment carries a page, which is reported as a fact about the segment rather than about the source: a *paged* document can hold page-less elements — spreadsheet-print manifest tables tail the stream with no page anchor because they span pages rather than sitting on one — so a `None` does not by itself mean the source has no pages, and the caller populating a ground-truth sidecar, whose `page_range` separates "no pages exist" from "none was produced", makes that call with the whole document in view. The budget is in tokens because that is what the packer counts; the human-facing word count is recorded alongside on each segment rather than converted at the boundary, so no rounding sits between the two. Budget, ceiling and oversize behaviour are configuration; the token counter is passed in rather than constructed, so the caller chooses the tokeniser its budget is expressed in and segmentation stays offline-testable. Re-run determinism is pinned rather than assumed — the same stream and configuration re-segment to identical boundaries — because the digest chain a ground-truth unit records about itself is decorative without it. Determinism *across processes under a randomised hash seed* is deliberately not claimed here: nothing in this module iterates a mapping, so there is no hash-order surface to guard, and that test belongs with the renderer whose requirement asks for it.
- **A pre-release no longer becomes `latest`.** `release.yml` and the publication workflow both fire on `v*`, so `v1.0.0-rc1` would have published under its own version *and* moved `latest` — making a release candidate what every deployment following that tag picks up, the opposite of what cutting a candidate means. `latest` now moves only for a final release; a version carrying a hyphen after it, as SemVer spells a pre-release, publishes under its own tag and leaves `latest` alone. - **A containerised run names the image that produced it.** The run record gains an `image` block — whether the run was containerised, the image reference, and the digest — so `<run>/manifest.parquet` names the artefact alongside the version and commit. The digest has to be handed in rather than discovered: it is content-addressed *after* the push, so it cannot be baked into the image it names, and a container cannot read its own labels from inside. Compose supplies it from the same value R3 pins each service to, and the local override empties it, because those services build and naming a published image there would be the one dishonest outcome available. Four outcomes, each recorded rather than left empty: a digest; a tag, which identifies no bytes and so is never recorded as one; a container given no reference; and a run outside a container, which says so. `record_version` goes to 2 — telling a record with no image block from one whose run was not containerised is exactly what a reader inferring from field presence would get wrong. The `partial` list carries the limitation even when the digest is present, and especially then: the value is operator-supplied, so the record must not read as though the run verified the image it was running in.
- **Both images are published to GHCR on a release, and the digest is recorded.** Nothing published either image, so every environment built its own and no deployment could name what it was running. A new `publish-images` workflow pushes the pipeline and console images to `ghcr.io/deepcivic/womblex` and `ghcr.io/deepcivic/womblex-console` on each `v*` tag — under the version and `latest` — and writes the digest each one received into `deploy/images.env` on the default branch. A digest rather than a tag, because a tag can be moved to point at different bytes and dependencies resolve at image build time, so the commit does not determine the image. `REQUIRE_STAMP=1` is set on this path, so an image that cannot name its commit fails the build rather than reaching the registry, and each published image is pulled back by digest and asked what it was built from. Publication holds no credential of its own — GHCR takes the ambient `GITHUB_TOKEN` — and the workflow can be run manually to publish an `edge-<sha>` tag without cutting a version or moving what a deployment follows.
- **The compose stack runs a published image without building, and still builds locally.** The base file now names both images and builds neither; `docker-compose.local.override.yml` carries the five `build:` blocks. Compose builds whenever a `build:` key is present, so an `image:` beside one is not a switch — moving the blocks is what makes the choice a declared one: pass the override to build from the working tree, pass `--env-file deploy/images.env` to run the pinned artefact. The override is already the file a developer passes, so local work is unchanged. Each reference is `${WOMBLEX_*_IMAGE:-<latest tag>}`, so a recorded digest overrides the tag with no file edit.
- **Every compose service has a recorded decision about where its image comes from.** Five of the eight services in the base compose file build from source and none references an image of this project, so every environment builds its own and no deployment can name what it is running. `docs/deployment-images.md` enumerates all thirteen entries across both compose files with a verdict each, records the two weaknesses as one — a local build and a moving third-party tag are the same unidentifiability in different places — and notes that two of the three third-party references carry no tag. `tests/test_deployment_images.py` reads the document back against the files, so a service added later that builds from source without a decision fails a test rather than joining the stack silently.
- **Container images build in CI and name the commit they were built from.** Two Dockerfiles existed that no workflow built, so a change that broke an image was found on deploy rather than on the pull request that caused it. A new `images` job builds both — the pipeline image and the console image, on a runner each, because the two do not comfortably share one runner's disk — and exercises what it built rather than only compiling it: the pipeline image runs the CLI, the console image starts and answers `/api/health` over the vendored demo corpus it already carries. It builds the instructions a deployment builds, with nothing overridden but the provenance compose does not supply, so there is no CI-only variant that could pass while a real build fails. Layer caching is per image and keyed on the Dockerfile's own layers, which is what makes it affordable on every change.
- **An image records its commit, as metadata and as a stamp the run can read.** `SOURCE_COMMIT` is a build argument rather than something the build discovers: the context excludes `.git`, and a context is a copy of a work tree rather than one, so there was nothing to read — which is why a containerised run resolved its commit as `unavailable` even though `store/build_info.py` had known how to answer since P10. The commit lands twice, for two readers: as `org.opencontainers.image.revision` on the image, readable with `docker inspect` without running it, and as the `_build_stamp.py` the *installed* package carries, which is the copy `build_info` asks and so the one a run reports. It is written as the last layer rather than into the source tree before `pip install`, because a per-commit value underneath the dependency layer would re-resolve the whole vision/ML stack on every push. `REQUIRE_STAMP=1` makes an unstamped build fail — set on a published build, unset by `docker compose build`, so a local image still reports `unavailable` with a reason rather than acquiring a claim it has not earned. CI asserts both directions: the label and the resolved stamp against the commit, and a published build given no commit against a non-zero exit. A stale stamp from a local `python -m build` is kept out of the context, so the only commit an image can name is the one its build was given. What identifies a published *artefact* is a digest, which waits on there being a publication.
- **The console can select the subdirectory a nested corpus refuses.** `GET /api/execute/ingest` takes the same ingest-relative `input_prefix` the enqueue already accepted and echoes it back, so the composer previews a prefix and posts that same string — preview and dispatch cannot disagree about which documents a press will run. Both now go through one listing helper in `ui/execute.py` rather than two walks that agreed by inspection, which is what makes the number on the screen the number that prefix enqueues. What a prefix *means* is settled once, in `cli/_shared.py` beside `select_supported`, so `womblex enqueue --input-prefix` reads it identically. A nested layout still reports the refusal rather than a count, and now also names the immediate subdirectories holding documents, each with its document count and the prefix that selects it: the recovery the refusal's message describes was CLI-only, because repointing a deployment's ingest location is configuration rather than a control, so an operator working through the console could read why their corpus was rejected and do nothing about it. The counts are what distinguish an intended corpus from a stray directory, and the prefixes compose, so a second level down is one more press rather than a restart from the root. A prefix that escapes the ingest root is refused as bad input (400) before anything is listed — `RemoteStore` strips slashes but does not resolve `..`, so this is the same treatment `is_safe_run_id` gives a climbing run id, refused rather than sanitised. Every other spelling normalises to one key scope first — a trailing or doubled slash, a `.` segment — because the keys under the prefix are not only a listing: they are what the queue carries, what the worker downloads and what P1 records as each document's `source_relpath`, and an object store has no path semantics to collapse `inbox/./a.pdf` back onto `inbox/a.pdf`. `womblex enqueue --input-prefix` had published those keys since it gained the flag, measured at `./2026-08/a.pdf` and `2026-08/./a.pdf`; it takes the same rule now, and its "no source documents location" guard reads the normalised prefix, so `--input-prefix ./` without `--ingest` is refused rather than enqueueing the whole store, the run's own output included.
- **Every chunk row carries its token count.** `CHUNKS_SCHEMA` gains `token_count`, measured by `chunker.token_counter` — the callable semchunk budgeted each split against — rather than re-derived downstream. It earns a column because it is the one length that cannot be recovered from the row: character and word counts follow from `text`, a token count needs the tokeniser loaded, which is the whole cost a consumer was previously paying to ask how full a chunk was. The count is taken in `chunk_batch` **after** `_repair_redaction_splits`, so a chunk merged to heal a `<REDACTED>` marker split across a boundary reports the merged text rather than the sum of two pre-merge counts — a sum that would be wrong for exactly the chunks the repair exists to produce. The count is **exact at or below `chunk_size` and a floor above it**, which is stated on the column rather than left to be discovered: `chunkerify` derives `max_token_chars` from the tokeniser's vocabulary whenever it exposes one, so the counter it builds short-circuits over-budget text to `chunk_size + 1` rather than tokenising it — measured, not inferred, at 65 for a 193-token string under a 64-token budget, and true of the production kanon-2 path rather than only of an explicit `create_chunker(max_token_chars=...)`. Every chunk semchunk emits is within budget and so counts exactly; the one chunk that can exceed it is a repair-merged one. Recovering its true figure means tokenising again with a second counter, which is the re-estimate the column exists not to be, so the saturation is documented and pinned by a test instead. `TextChunk.token_count` defaults to `None` for a chunk built outside `chunk_batch`, and shards written before the column read back with it back-filled null on the existing `_CHUNKS_BACKFILL` convention rather than failing, so a completed run stays readable. No reader changes — the console's sidecar table and the Chunk Inspector take their columns from the schema.
- **A published row resolves back to its source document.** New `store/source_resolver.py` closes the provenance chain's return leg: hand `SourceResolver` a run's manifest and a corpus and it takes any sidecar row's `source_hash` back to the file, verified against the bytes. Resolution is by the root-relative path P1 records rather than by an absolute one, so a corpus moved to a new root re-resolves against it with no rewrite — asserted as a test rather than in prose. **Every call returns a `Resolution`** with a status and a reason, never an empty return: a consumer walking a whole run gets an account of the rows that failed rather than a shorter list. The statuses are chosen so the useful cases stay apart — a corpus re-saved with different bytes reports the hash mismatch *and the path it found*, rather than the less useful "not found"; a document moved within the corpus is found by hash instead; a row with no manifest entry says exactly that. The two hash bases are distinguished rather than conflated: a file ingest hashes source bytes (`store/output.py`), the pre-extracted records ingest hashes record id plus text (`ingest/records.py`), so there is no file to hash for a records row — it is *declined by name*, with `*.provenance.parquet` given as the back-link that does answer for it, which is a different outcome from a document that has gone missing. Both resolution paths go through `select_supported` in `cli/_shared.py` — the one enumeration rule P11 settled and every entry point already ingests by — so a document the resolver returns is one a run could have processed, and a corpus with documents in subdirectories is refused by the index exactly as a run refuses it. That is the last acceptance criterion's shared helper rather than a second walk that happens to agree today. The full-corpus index is lazy and consulted only when the path has not answered, so resolving a corpus still sitting where the run found it costs one file read per lookup rather than the full scan the requirement's notes anticipated. Scoped to the NLP path: the standalone register ingests carry no `source_hash` and are not addressed. `SourceResolver.for_run` takes a run root, a shard directory or a manifest Parquet — preferring the consolidated `manifest.parquet` P9 publishes — and defaults the corpus to the manifest's own `ingest_root`, refusing an object-store or mixed root at construction rather than resolving nothing row by row; `--root` overrides it, which is how a moved corpus is re-resolved. `womblex resolve-source` joins `verify-shards` in `cli/verify.py`, both of which inspect a finished run without changing it, and exits 2 when any row is unresolved but 0 when a declined hash basis is the only thing standing between a row and a file — a row that is accounted for is not a row that is missing. Landed as two merges for the size cap: the resolver, then the entry point and the command.
- **Every Parquet names the local models the writing process had loaded.** A sixth `womblex.*` footer key, `womblex.models`, carries each model's name and a digest over its bytes, and the run record unions them across a run. Which local model produced an output was not recoverable after the fact — nothing on disk said whether a shard was OCR'd by one layout model or its replacement, and a model directory is swapped in place far more often than it is renamed — so, per "carried, not recomputed", the fact is stamped at write time rather than inferred at finalisation. `utils/models.py` is the choke point every model path in the library already goes through, so resolution is now also the record: an artefact that resolves is noted, and `loaded_models()` digests each over its contents. A directory digests every file beneath it, contributing both the root-relative path and the bytes, so the digest recomputes from the model files alone and a rename inside the tree is a different artefact rather than the same one. Digests are lazy and cached per path — a run that loads no model pays nothing, one that does pays the hash once rather than per file written — and a caller only *probing* for presence (`utils/availability.py`) passes `record=False`, since a resolution leading to no load would overstate what ran. The key is deliberately not a field on `RunStamp`: a stamp is declared once at the start of a run and models load lazily during it, so a field filled in at `declare` would be empty on every file. Read at footer time instead, each file names what was loaded when it was written, and the union across a run's files is the run's set. A process that loaded no local model writes no key, on the same terms an unstamped file is written for a run that cannot be named. Footer metadata stays additive, so no reader changes.
- **The run manifest carries a record of what produced the run.** `<run>/manifest.parquet` gains a `womblex.run_record` footer key: the run id, version, commit and configuration digest; the corpus, document count, extraction methods and statuses; the stages observed to have run with their file and row counts; the local models loaded, each with a content digest; and the external services declared. Footer rather than columns because the record is run grain and the manifest is document grain — the rule `decisions.md` already states for run- and corpus-shaped provenance — and this file rather than a new one because consolidation is already the moment both finalisation paths pass through (`womblex run`'s end step and `womblex finalize`) and is already regenerable on demand, which is exactly the lifecycle the record needs. Everything is **observed, not declared**: the stages come from the run stamps the files themselves carry, so a stage that was configured and never ran is *absent* while one that ran and produced nothing is *present with no rows* — a distinction a list read off configuration flags cannot make; the documents, methods and statuses are counted off the consolidated rows. No configuration is consulted at all, because `womblex manifest` regenerates the record from the shard directory alone and may be re-run long after the run against a config that has since moved on; re-running over an unchanged run reproduces the record apart from its own timestamp. Credentials are structurally absent — an endpoint name, a region and a model id are the whole of what is read of a deployment — and a test asserts no credential value reaches the footer. What cannot be established is named in a `partial` list rather than omitted or invented: a run finalised before the run stamps existed produces a record saying so and still naming its documents, instead of one quietly claiming the run had no stages. Completes the provenance-chain link "run to account".
- **Every run names the Womblex build that produced it, not just the version.** A fifth footer key, `womblex.commit`, lands beside the four the run stamp already carries. A version alone does not identify a build — the same `0.5.12` is cut from every commit between two releases — so new `store/build_info.py` resolves the source commit and `RunStamp` carries it. Two sources answer, neither everywhere: the work tree is asked first (true in a checkout and in CI, never of an installed wheel, and preferred over a stamp because a stamp left behind by an earlier local build would be stale against the tree actually running), then `_build_stamp.py`, generated by the release workflow and gitignored so it never exists in a checkout. Where neither answers — a container today, a hand-built wheel — the value is `unavailable:<reason>` with the two reasons kept apart (`not-a-git-work-tree`, `git-not-installed`), a first-class value rather than an empty string or a default, which is the thing this was built not to do. A dirty work tree gets its sha suffixed `-dirty`: the bytes that ran are not the bytes at that commit, and reporting the sha bare would claim exactly what the record must not. Resolution is cached per process (a run asks for a stamp on every file it writes and this shells out), every git failure is bounded and swallowed rather than propagated, and the commit — like the version — is the *running* one at each writer rather than inherited, so a stage run at a later build says so. The package version also gains the definition it lacked: a test asserts `__version__` and the installed project metadata agree and fails when they drift, and a second asserts it is not the manifest's `parser_version`, which is the *schema* version and only looks like an answer to this question. The container stays `unavailable` until a published image carries a stamp — the honest answer rather than a gap, and its own piece of work.
- **Every downstream sidecar and the consolidated run manifest name their run too.** The four `womblex.*` run keys now land on all seventeen per-batch sidecar writers — chunks, normalised text, spellfix text and corrections, the three enrichment sidecars plus the persisted Document, the graph-refresh rewrites, embeddings, money spans and columns, entity links, PII spans and clean text, and chunk quality — and on `<run>/manifest.parquet`. A stage does **not** declare its own stamp: it inherits the run from a stamped sibling of the batch its sidecar sits beside (`stamp_for_sidecar` prefers `<base>.elements.parquet`, then the manifest, then any sibling — every file of one run carries the same run id and digest), and the consolidated manifest reads it back from the per-batch manifests. The fallback is load-bearing rather than defensive: a stage worker stages in only the inputs its contract declares, and `embed`, `link`, `pii`, `quality` and `graph-refresh` do not declare the elements shard — insisting on it would have left exactly those five unstamped on a worker and stamped locally. This is the only trustworthy source — a stage is handed a shard directory, not a run, and its own `dataset.run_id` is whatever config it was launched with, so a copied config would have it stamp a run it did not produce. It is also what makes the local and distributed stamps match by construction rather than by both invocations happening to be handed the same YAML. `run_id` and `config_digest` are inherited because they describe the *run*; `version` is the running `__version__` because it describes the *bytes*, so a stage run at a later build says so instead of repeating what extraction claimed. An unstamped or absent base shard yields an unstamped sidecar, and batches naming two runs leave the run keys off the consolidated manifest — the rule the ingest-root footer already follows for a mixed-root directory. `tests/test_run_stamp_sidecars.py` is the acceptance criterion's enumeration test: it walks every public writer in `womblex.store` and fails on one that is neither stamped nor in an exempt list that carries a reason per entry (the extraction writer, which takes its stamp explicitly; the JSON feedback record; the standalone register ingests and the pre-extracted records ingest, which are not runs; and the three whole-corpus E2E enrichment writers, which have no per-batch shard to inherit from — their only caller, `operations.write_batch_enrichment`, has had no caller of its own since in-batch enrichment was removed in 0.5.10, and is a fossil worth retiring separately). Completes the provenance-chain link "run to output", and is what P9's stage inventory reads: a stage that ran is now observable from the stamps rather than declared from a config flag. Footer metadata stays additive, so no reader changes.
- **Every extraction Parquet names the run that produced it.** New `store/run_stamp.py` stamps four namespaced footer keys — `womblex.run_id`, `womblex.version`, `womblex.config_digest`, `womblex.stage` — onto all four shard files, so a shard copied out of its run directory still says which run it belongs to and a file mixed in from another run is distinguishable from a native one. Previously the run id existed only as a directory name and was lost the moment a shard moved. `RunStamp` is declared once per run and re-pointed at each writer (`for_stage`), so the run id, version and digest cannot drift between one run's files; the caller supplies it for the same reason it supplies `IngestProvenance` — only the caller knows the run id — and an omitted stamp writes no run keys rather than inventing one. The digest is over the *validated* configuration (pydantic defaults and the AI-chunking validator both rewrite what the YAML supplied), so two YAML files differing only in formatting produce one digest; `paths` and `dataset.run_id` are excluded, the first because where a deployment keeps its files is not what the pipeline does — that exclusion is what makes a worker's stamp match the local run's for the same config and corpus — and the second because it is stamped in its own right. Wired at the two run entry points (`womblex run` and `cloud/worker.py`, both via `process_batch`); the one-off `womblex extract <file>` and the back-compat E2E chunk path stay unstamped, being no run, and a queue row naming no run publishes unstamped on the same terms an undeclared ingest root already gets — a malformed row costs the stamp, not the batch's extraction. Footer metadata is additive, so readers are unaffected. First half of the provenance-chain link "run to output"; the second half is the entry above it.
- **Manifest and Parquet footers record where the source document came from.** `MANIFEST_SCHEMA` gains `ingest_root` (scheme-qualified: `file:///srv/corpus`, `s3://bucket/inbox`) and `source_relpath` (the path under it), so root + relpath names the document and a corpus that moves to a new root re-resolves without a rewrite; `collection_id` is populated rather than left empty. The same pair is stamped into every extraction Parquet's footer key-value metadata under `womblex.*` keys, reusing the namespacing convention `store/register_manifest.py` already reads back from the register ingests, so a shard copied out of its run still names its corpus. New `store/source_provenance.py` holds root qualification, relative-path resolution and the footer keys; the root is declared by `paths.ingest_root` (new, optional) or `paths.input_root`, or by the enqueue invocation for a distributed run — never inferred from the working directory. Shards written before the columns read back with them empty (`_MANIFEST_BACKFILL`), and footer metadata is additive, so existing readers are unaffected. Masking is a stated non-goal: a `pii` run over a completed run leaves the manifest byte-identical.

### Removed
- **The console's report/feedback action is retired.** `POST /api/runs/{run_id}/feedback`, `ui/routes/feedback.py`, `store/feedback_output.py`, `readers.write_feedback`, `UISettings.feedback_dir`, `--feedback-dir` / `$WOMBLEX_UI_FEEDBACK_DIR` and the `X-Womblex-Reported-By` / `$WOMBLEX_UI_REPORTED_BY` handling are gone; the console's only writable surfaces are now dispatch and preset saving. `is_safe_run_id` moved to `store/retention.py`. Existing `feedback/` prefixes in a store are simply ignored. Sixth merge of the backend-subsystem plan.
- **The `verify/` package.** `run_verifications` — a two-pass structural check plus a weak-signal scan classifying a run `passed` / `warning` / `failed` — was defined, exported, and called by nothing; its own tests imported the helpers and never the entry point. It is deleted with its exports and `tests/test_verify.py`, rather than connected. Connecting it was never a rename: it expects one row per document carrying `document_id`, `source_path` and `text`, where the manifest names the first `doc_id`, expresses provenance as `ingest_root` plus `source_relpath` (P1), and carries no text at all — text and `confidence` are per-*element*, and `page_count` exists in no schema — so adapting it meant a grain change and narrative reassembly, which is a rewrite of a module nothing asked for. Its remit is also occupied: `process/quality.py` and `quality_stage.py` annotate chunk quality with a sidecar and a checkpoint. And the thing it does is the thing this repository declines to do on purpose — threshold-based quality scoring, ruled out in the contributor guidance while the corpus is still poorly understood. Verification that is actually wired is unaffected and unchanged: `verify_shard_persistence()` after every batch write, `womblex verify-shards` over a directory, and `womblex resolve-source` back out to the corpus. `pandas` stays a dependency — four other modules import it. `cli/verify.py` is a different file and stays.
- **The `security` and `Secret scan (history)` CI jobs.** `.github/workflows/ci.yml` now runs `test` and `Console frontend (ui/)` only. This takes CI's semgrep SAST (Python + OWASP + the local rulesets, blocking), the informational `pip-audit` dependency audit, the whole-tree detect-secrets pass and the KeyHog working-tree + reachable-history scans out of the pipeline; nothing checks a pushed commit for credentials or injection sinks any more. The commit-time hooks in `.pre-commit-config.yaml` still run detect-secrets and the local semgrep rulesets, so the pragmas and `.secrets.baseline` below still do their job — but they are opt-in per clone (`pre-commit install`) and `--no-verify` walks past them, where CI could not be skipped. `.semgrep/rules/`, `.secrets.baseline` and `.keyhogignore` are retained, so restoring the jobs is a revert of this commit.

### Fixed
- **The G-NAF PSV ingest no longer reads the header row as data.** `ingest_psv` set `column_names` from the static schema but never told pyarrow to skip a header, on the assumption — stated in the module docstring — that G-NAF PSVs are headerless. The distribution ships each Standard and Authority Code PSV with an uppercase header row naming its columns, so every extracted table gained a spurious first data row carrying the column names (and, on the files that begin with a UTF-8 BOM, a BOM-prefixed one), shifting the whole table down by one. The ingest now detects that header — the first line's fields, case-folded with any BOM stripped, equal the schema's columns — and skips it, while a genuinely headerless file is still read as-is; column names always come from the schema regardless. Surfaced by the benchmark's new cell-wise PSV scoring, which failed structural fidelity and data integrity on the row shift.
- **`verify-shards --input-dir` no longer reports drift that isn't there.** Its source-file count carried its own extension list (`.pdf .docx .csv .xlsx .txt .html .htm`) and its own one-level walk, both of which disagreed with the rule a run ingests by (`.pdf .csv .xlsx .xls .docx`, via `select_supported`). It counted `.txt`, `.html` and `.htm` files a run passes over, and missed the `.xls` files a run takes — so a corpus holding a `readme.txt`, or one holding legacy Excel, produced a source-vs-manifest gap in one direction or the other on a run that had processed every document correctly. The count now comes from `discover_files`, the shared helper, so it is the count the run itself would produce. A nested corpus — which a run refuses since P11 — reports `None` rather than a number: `source_count` already carries `None` for "not available", and no count is the honest answer where a run would ingest nothing. This was the second enumeration rule P11 set out to remove and the one P2's resolver was made to avoid; it survived in the audit because nothing compared the two lists. Found by reading, not by a failure.
- **The run record no longer under-reports a distributed run, or carry an AWS account id.** Three defects found auditing P9 against its own acceptance criteria. *`womblex finalize` stages in only the manifests*, so a record built from that directory named extraction and nothing else — and a missing stage is indistinguishable from one that never ran, which made it silent rather than merely incomplete. `finalize` now reads each shard's footer where it lives (`RemoteStore.read_parquet_footer`: a ranged read of the footer and row count, not a download) and passes the observations to `build_run_record`, so no filesystem abstraction reaches `store/run_manifest.py`; a directory that does hold manifests alone says so in `partial`. Served models are the one part footers cannot stand in for — they are read from the embedding sidecars' *rows* — so a record built over a directory that is not the whole run declares that limit separately rather than letting it hide behind the first. *An endpoint given as a full ARN* put the account id from the ARN's fifth field straight into the record, which the criterion forbids by name; the ARN is now parsed strictly by field index — region 3, account 4, resource 5+ — so no shape of it, including one truncated at the account, can be emitted as the endpoint name. *RapidOCR's fallback models* ship inside its own wheel and are loaded by the library, never passing through `resolve_local_model_path`, so a run that OCR'd on them recorded no OCR model at all; `record_loaded_path` notes them at the fallback site and they are digested like any other artefact.
- **The secret scan passes.** It has failed on every run since the scanner landed: `.secrets.baseline` was generated in the same commit that added `docker-compose.local.override.yml` and the storage-options credential tests, and `detect-secrets scan` walks files git already knows about — so the baseline never covered the four sites that same commit introduced, and both the `security` and `Secret scan (history)` jobs went red immediately and stayed there. Fixed at the sites, per the convention in CLAUDE.md and README: an inline `# pragma: allowlist secret` with a reason on the bundled-local Postgres DSN and MinIO default in the override compose file, and on the three fake-credential assertions in `tests/test_cloud.py` (the same literal appears twice in one test, and both occurrences need one). A pragma travels with the line where a baseline entry goes stale as soon as the file is edited — which is the second failure behind the first: the baseline's `docker-compose.yml` line numbers had drifted, so the hook rewrote the file and exited non-zero even once no secret was reported. Those line numbers are refreshed here, and the regeneration trap is recorded beside the command in `.pre-commit-config.yaml`.
- **Two documents whose store keys share a basename are both extracted.** A worker staged its batch's documents into one flat scratch dir, so `2026-07/report.pdf` and `2026-08/report.pdf` — routine under a dated or per-agency upload layout, which `list_files(recursive=True)` has enumerated since the ingest-listing fix — landed on one local file: the second won, one document was extracted twice and one not at all, and the recorded ingest provenance was the survivor's. `RemoteStore.download_to_dir` gains `nested=`, which mirrors each key's prefix under the staging dir, and `cloud/worker.py` stages documents that way. A key is canonicalised and asserted to stay under the staging directory before anything is written to it, so a `../` in a queue row cannot escape the scratch dir. Staging stays flat everywhere else — the shard, manifest and checkpoint callers pull siblings of one prefix into the flat directory the `*_shards()` entry points and readers expect — and the collision warning is retained there.

### Changed
- **The three enrichment sidecars join on `source_hash`, like every other sidecar.** `*.enrichment_entities.parquet`, `*.enrichment_meta.parquet` and `*.graph_edges.parquet` named their document identity column `document_id` while every other schema in `womblex.store` named it `source_hash` — with byte-identical values, because the sharded enrich stage wrote the source_hash into it. The cost was not the name but what consumers carried to work around it: a note in `store/enrichment_output.py`, restating notes in the link and graph-refresh stages and in the frontend's own type, a per-sidecar join column in the console's sidecar table, a suffix-to-column map derived from it for the stage-presence scan, and a loop in the Chunk Inspector renaming the field before it reached the frontend.
