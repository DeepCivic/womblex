# Chunking Behaviour

Generated by the benchmark's `accuracy/test_chunking_behaviour.py` — do not edit by hand.

**Date:** 2026-09-11
**Chunker:** semchunk via `process/chunker.py`, `chunk_tables` on
**Config:** `isaacus/kanon-2-tokenizer`, chunk_size=480 tokens — the production configuration in `configs/example.yaml`, not a test stand-in

**This is a behaviour baseline, not an accuracy score.** No chunking ground truth exists for any fixture, so nothing here is measured against a reference the way the other reports in this directory are. What the suite does gate are the contracts that hold without one: every chunk within budget (unless the `<REDACTED>` split repair merged it), narrative offsets indexing back into the narrative, no empty chunk, contiguous `chunk_index`, and no `elem_order` anchor on a narrative chunk.

**Scope.** The womblex-collection documents only. The OCR image fixtures (FUNSD, IAM, DocLayNet) are single-page crops whose text falls below the chunk size, so chunking them measures nothing — they are out of scope rather than tabulated.

## Token counts are the chunker's own

The token columns are read from `CHUNKS_SCHEMA.token_count`, which carries the count `chunker.token_counter` produced — the number semchunk compared against `chunk_size`, not a re-estimate. It is exact at or below the budget and a floor above it, so a repaired chunk's `Max tokens` reads as `chunk_size + 1` rather than its true length. See the column's note in `docs/dataflow.md`.

## Known limitations

1. **No chunking ground truth** — there is no human-annotated "correct" chunking for any fixture. Evaluation is limited to structural metrics and the invariants above.
2. **No semantic coherence metric** — chunks are measured by size, not by whether they hold semantically complete units. Measuring that needs either annotation or a downstream retrieval task.
3. **Spreadsheet row-level chunking is close to trivial** — CSV and XLSX rows are short enough that most become single chunks. The chunker adds little there; it is the element-stream shape (one `sheet_cell` element per cell) that sets granularity.
4. **Redaction interaction is not exercised here** — `has_redaction` is set from the marker in the chunk text, which the redact stage writes. This suite chunks extraction output directly, so no chunk carries one. The detector's own accuracy is in `REDACTION_HANDLING.md`.
