Generated by the benchmark's `accuracy/test_backend_parity.py` — do not edit by hand.

**Date:** 2026-10-06
**Plan:** `docs/plan-permissive-deps.md`, merge H-B

**This is the repeatability baseline, not a backend diff.** The permissive-dependencies plan is at Phase 0 — no second PDF backend exists yet (no `ingest/pdf` seam, no pypdfium2 adapter). Both sides of every comparison below are the current fitz-based build, run twice independently. P2 onward's identity gate reads this report ("identical `content_digest`, `PageProfile` and `RedactionReport` on every fixture, as reported by H-B"); that gate assumes running the same code twice gives the same answer, and this is where the assumption is checked, before there is anything to diff it against.

**Axes compared,** per document: open failures, page count, doc type, every `PageProfile` field (the page rect included), per-page plan operation, element kinds and counts, `content_digest`, table shapes, form-field counts, and the full per-page geometry of every detected redaction — bboxes, not just their total.

**Where this falls short of the gate's wording,** so it is not read as wider than it is:

1. **Not whole documents.** Every PDF is capped to its first 20 pages, so each `content_digest` here is of a truncated document. A divergence that first appears deep in the 406-page Auditor-General report is outside this gate. Uncapped, that one fixture's OCR-dispatched pages pushed a single run past an hour.
2. **PDFs and images only.** The harness opens with `fitz`, so the DOCX, XLSX, CSV, XML and TXT fixtures never reach it. P2 ports `strategies_file.py` as well; those formats are gated by Womblex's `tests/test_default_digest.py`, which pins four of them.
3. **No CER.** Neither between backends (there is only one) nor against the Auditor-General / ACT-ECI transcripts, which waits on the ground-truth revision.
4. **No layout.** Redaction detection runs with `use_layout_filter=False` throughout, so nothing here loads the layout model or scores against DocLayNet.

## Known limitations

1. **Single backend.** Every comparison above is fitz against itself. A real backend diff needs P1 (the `ingest/pdf` seam) and at least P5/P6/P7 (the pypdfium2/pdfplumber adapters) to exist. Until then the comparison is reflexive, so the element, table and redaction totals above — not the identical count alone — are what says the baseline covered anything.
2. **No reference text.** Nothing here is scored against a transcript — it is a self-consistency check, not an accuracy measurement. See the other accuracy reports in this directory for those.
3. **OCR nondeterminism, if any, would show up as a mismatch here** — a flaky confidence score, a model with unseeded randomness — rather than being distinguished from a real backend difference. Once a second backend lands, a document that mismatches run_1-vs-run_2 under the *same* backend needs separating from one that only differs across backends, or the latter's signal is confounded.
4. **Timing is indicative, not a measurement.** It is wall time on one developer machine with no repetition beyond the two runs, and most of it is work any two PDF backends share — the phase split in the summary is there to show how much. Treat a backend comparison's timing as a smell test, not a benchmark.
